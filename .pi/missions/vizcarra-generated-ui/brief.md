# brief: vizcarra-generated-ui (Track B, 0.8.1)

## Context
Track B (UI codegen extraction) has built the full view generation pipeline:
the `wb generate views` CLI command with `--template-package` product-skin
overrides, `base_template` and `{% block %}` override points on all three
archetypes (checklist, landing, dashboard), and `generate-views` wired into
`generate-all`. All of this has been proven against real farm data (0.7.3).

The next step is to **consume this pipeline on a second product repo**.
Vizcarra Guitars currently has a single hand-generated landing view
(`AdminLandingView` in `views_auto.py`, generated by the old `generate_views`
management command before the pipeline existed). It does not use the
`wb generate views` CLI, does not have a template package, and does not
exercise the checklist or dashboard archetypes.

This mission proves that the view codegen pipeline generalises beyond the
source engagement (farm). It also sets up Vizcarra for the `vizcarra-cutover`
mission (1.0.0) by ensuring the generated UI is functional, styled, and
tested against real Coda data.

## Goal
Regenerate Vizcarra's existing domain views through the `wb generate views`
pipeline, add archetype-generated views (checklist, dashboard) where they
match Vizcarra workflows, and prove the generated UI works end-to-end against
real Vizcarra Coda data.

## Repo
migration-workbench (primary, if any pipeline gaps are found) + vizcarra-guitars

## Starting State
- `wb generate views` CLI exists with `--archetype-checklist`, `--archetype-landing`,
  `--archetype-dashboard`, and `--template-package` flags (0.7.3).
- vizcarra-guitars has `models_auto.py` (4 models: Clients, WorkOrders,
  Instruments, ArchivedWorkOrders), `admin_auto.py`, `import_domain.py`.
- vizcarra-guitars has a hand-generated `views_auto.py` with `AdminLandingView`
  (landing archetype, generated by old `generate_views` command in 0.7.1).
- vizcarra-guitars has `urls_auto.py` routing a single landing URL.
- vizcarra-guitars has 4 passing `test_generated_views.py` tests.
- Workbench venv in vizcarra-guitars is at 0.5.0 (PyPI). Needs upgrade.
- Workbench: `make chassis-gate` green (1743 tests).

## Scope

### In-scope

#### 1. Upgrade vizcarra-guitars to latest workbench
- Install local migration-workbench as editable or bump venv to >=0.7.3.
- Bump `pyproject.toml` dependency to `>=0.7.3,<1`.

#### 2. Template package for vizcarra-guitars
- Create `backend/templates/` or similar with a base template (`base.html`)
  using the Vizcarra Guitars brand.
- Wire it into `wb generate views --template-package`.

#### 3. Regenerate landing view via pipeline
- Create landing config YAML for the AdminLandingView (summary cards from all
  4 model counts).
- Run `wb generate views --archetype-landing config/landing.yaml
  --template-package backend/templates` to regenerate `views_auto.py`.
- Verify the existing tests still pass with the regenerated view.

#### 4. Add archetype views matching Vizcarra workflows
- Evaluate Vizcarra domain for archetype fit:
  - **Checklist:** Work Orders lifecycle (repair status tracking) maps well
    to a weekly checklist with HTMX toggles.
  - **Dashboard:** Instrument inventory (stock status by type) maps to a
    dashboard with alert cards and detail sections.
- Where fit is confirmed, create config YAML and generate the view.
- Register generated URLs in `urls_auto.py`.

#### 5. Real-data tests
- Update `test_generated_views.py` to exercise each generated view against
  real Coda-imported data (or seeded data matching the real schema).
- At minimum: landing view shows correct row counts, checklist renders rows,
  dashboard shows alert cards.

### Out-of-scope
- Production styling / brand polish (functional correctness is the gate).
- Replacing the Coda doc in the wild (that's 1.0.0 `vizcarra-cutover`).
- Adding new archetypes not yet in the pipeline.
- MWBS Report-driven auto-generation (direct YAML config is fine).
