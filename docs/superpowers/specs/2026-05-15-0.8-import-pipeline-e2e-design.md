# 0.8 Import Pipeline End-to-End — Design

**Date:** 2026-05-15
**Status:** Draft

## Summary

Exercise the import generator with multi-model bundles, harden column transforms
and error handling, and wrap import tiers in per-tier `transaction.atomic()`
savepoints. This directly serves v1.0 criteria 2 (schema design loop — Author
importer phase) and 3 (prerequisite for deployment).

## Current state

- `generate_import` renders import commands from contract YAML with `import_config`
  blocks, but has never been exercised end-to-end with a multi-model bundle.
- `BaseImportCommand` wraps the entire pipeline in a single `transaction.atomic()`.
  If any tier fails, the entire run rolls back.
- Error handling has three codes (`missing_required`, `stale_fk`,
  `namespace_mismatch`) but no per-row exception catching. An `IntegrityError`
  or type coercion `TypeError` aborts the entire import.
- `column_map` multi-source and `field_transforms` shipped in 0.4.0 but have no
  integration tests.

## 2. Atomic tiers

### API surface

New CLI flag: `--tier-atomic` (default: `True`). Wraps each `self.tier()` callback
in a `transaction.atomic()` savepoint. Preceding tiers' rows persist even if a
later tier fails.

Complement: `--no-tier-atomic` disables per-tier savepoints (single-transaction
behaviour matching current default).

### Implementation

Modify `BaseImportCommand.tier()`:

```python
def tier(self, title, callback):
    self.stdout.write(self.style.SUCCESS("\n" + "=" * 70))
    self.stdout.write(f"{title}\n")
    self.stdout.write("=" * 70)
    if self.tier_atomic and not self.write_disabled:
        with transaction.atomic():
            callback()
    else:
        callback()
```

Modify `BaseImportCommand.handle()`:

- New attribute `self.tier_atomic` set from `--tier-atomic` / `--no-tier-atomic`.
- When `--tier-atomic` is on AND `atomic_apply` is on, the outer `transaction.atomic()`
  wraps the whole pipeline, and each `tier()` creates an inner savepoint.
- When `--validate-only`, the outer transaction still rolls back everything at
  the end (savepoints inside are fine — they all get rolled back).
- When `--no-tier-atomic`, behaviour matches current (single transaction, no
  per-tier savepoints).

### Per-tier error catching

When `tier_atomic` is on and a tier callback raises an unhandled exception:

- The savepoint rolls back that tier's rows.
- The exception is caught, recorded in `self.tier_errors[title]`, and printed
  as an error.
- The pipeline continues to the next tier.
- The final summary includes `tier_errors` alongside `row_errors`.

This means: `tier()` wraps `callback()` in a try/except. If the callback raises,
the savepoint rolls back, the error is recorded, and execution continues.

### Idempotent re-import

After a tier fails and rolls back, re-running the import recreates the same rows
because `update_or_create` is idempotent on `unique_on` keys. Preceding tiers'
rows are preserved.

### Tests

`importer/tests/test_atomic_tiers.py`:

- Test that `--tier-atomic` (default) preserves tier 1 rows when tier 2 fails.
- Test that `--no-tier-atomic` rolls back everything when tier 2 fails.
- Test that `--validate-only` with `--tier-atomic` still rolls back everything.
- Test that `--dry-run` with `--tier-atomic` skips all writes.

## 3. Error handling hardening

### Per-row exception catching in generated import methods

Currently, an `IntegrityError` or `TypeError` from a single row aborts the entire
import run. The generated `_import_<model>()` methods should wrap the per-row
`update_or_create` call in a `try/except` that:

- Catches `django.db.IntegrityError` → records `unique_violation` error, continues.
- Catches `Exception` → records `row_exception` error, continues.
- Both increment `self.stats[model_name]["error"]` and add a structured error
  via `self.record_row_error()`.

This change is in `import_generator.py` — the template that renders import methods.
The generated code gains a `try/except` around the row-processing block.

### New error codes

Add to `FAILURE_SIGNATURE_OWNERSHIP` in `importer/errors.py`:

- `type_mismatch`: owner `data-contracts`, severity `medium`, recovery "correct
  source data types and rerun --validate-only"
- `unique_violation`: owner `data-contracts`, severity `high`, recovery
  "deduplicate source data or adjust unique_on fields and rerun --validate-only"
- `row_exception`: owner `import-runtime`, severity `high`, recovery "review
  row-level errors in summary artifact before retry"

### Per-model row errors in summary JSON

Currently `row_errors` is a flat list under `results.row_errors`. Add a
per-model breakdown: each model's outcome dict in `results.models` gains a
`row_errors_count` field. The existing flat list is preserved for backward
compatibility.

### Parser null handling

Expand `importer/tests/test_parsing_edge_cases.py` to cover:

- Empty string, whitespace-only, `"N/A"`, `"-"`, `None` for each parser.
- `to_int("", 0)` → 0, `to_int("  ", 0)` → 0, `to_int("N/A", 0)` → 0.
- `to_decimal("", "0")` → `Decimal("0")`, `to_decimal("  ", "0")` → `Decimal("0")`.
- `to_bool("")` → False, `to_bool("N/A")` → False, `to_bool(None)` → False.
- `parse_iso_date("")` → None (should not raise).
- `to_int_or_none("0")` → None, `to_int_or_none("")` → None.

## 4. Column transform edge cases

### bundle_reader multi-source contract

`bundle_reader.py` currently skips multi-source `column_map` entries (lists) when
building `normalized_row`. The generated import code handles multi-source by
reading individual columns from `row.get()`. Verify this contract is documented
and test it:

- `test_bundle_reader_edge_cases.py`: Multi-source list entries are not present in
  `normalized_row` (they are handled in the generated import method).
- Aliases resolve differently than canonical headers.
- `default_values` fill missing keys.

### field_transforms end-to-end

- `test_column_transforms.py`: Load contract with `field_transforms`, generate
  import command, verify generated lambda expression, run against test data,
  assert transformed values. Test null part handling (empty string in one of
  the multi-source columns).

### Import generator edge cases

- `test_import_generator.py` (extend existing): Test that `field_parsers` override
  correctly generates `self._parse_date(...)` instead of auto-inferred parser.
  Test that `unique_on` with FK fields generates correct variable assignments
  (FK variable already resolved, not re-read from row).

## Non-goals

- **Real corpus with external API calls.** The test fixture uses local CSV files
  only (`snapshot_bundle` mode). No Google Sheets or Coda network calls.
- **Performance testing at scale.** 100k+ row imports are deferred to 0.9+.
- **New provider adapters.** No Coda or Sheets changes.
- **View manifest / discovery pipeline.** That's 0.9 scope.

## v1.0 criteria served

- Criterion 2 (schema design loop): Completes the Author importer phase with
  tested, hardened imports.
- Criterion 3 (production deployment prerequisite): Atomic tiers and error
  handling make imports safe enough for production deployment.
